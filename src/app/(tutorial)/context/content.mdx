The last three chapters built a chat assistant. Each new power turned out to be the same trick: hidden text added to the conversation.

The model's own thinking, tool results, skills, saved notes — all of it is text quietly slipped into the transcript ([Chat Models](/chat), [Reasoning](/reasoning), [Agents](/agents)).

All the text a model can see while it answers your prompt is called the **context**. This chapter is about keeping that context under control.

## Your app and the server

The model does not run on your phone. Two parts work together.

The **app** on your device shows your chat and holds the whole conversation. The **model** runs on the AI company's **server**, far away.

When you need a reply, the app sends the whole conversation to the server and asks what comes next. The server answers, then forgets you. It keeps no memory between requests. Each one stands alone — that is what **stateless** means.

## Reusing the work: the KV cache

Rereading the whole conversation on every request sounds insanely wasteful. Fortunately the server does not have to.

When the model reads a token, it works out a key and a value vector for it, back from [Attention](/attention). These depend only on that token and the ones before it, so once computed they never change. The **KV cache** on the server saves them and reuses them, instead of redoing the work.

There is one catch. A saved vector only counts if the text before it has not changed. So the cache reuses the unchanged **prefix** at the front, and the model computes only the new message at the end.

## A shared, temporary cache

The cache is not yours, and it does not last. The server keeps one pool of the prefixes it has needed lately, for everyone at once.

So you sometimes reuse a prefix from a stranger's chat. The **system prompt** and the standard tool list sit at the front of almost every request — one cached copy serves everyone, so they are nearly always ready.

But the pool is limited and it expires. Come back to a chat after a few hours and your prefix is probably gone, so the server computes it all over again.

## Subagents: reuse the cache and keep it clean

Some jobs are big and messy: read forty files, chase a bug. Do that in your main conversation and it fills with junk.

A **subagent** is a fresh model with its own empty context. It does the messy work in there and hands back a short answer. Your context stays clean.

Subagents also reuse the cache. To use a big **skill** that is already cached, start the subagent with that skill — the reused prefix — then add a line or two of instructions. Long **reasoning** works the same way: let the subagent think through the dead ends and keep only the answer.

A subagent is also good for a second opinion. Ask a fresh one to critique your work and it judges with clear eyes, not tangled in the thinking that produced it.

## When the pile still grows: compression

Subagents keep new mess out. But your own conversation still grows, turn after turn.

When it will not fit, you **compress** it: swap a long stretch of old turns for a short summary, and keep going.

It is a bit like sleep — take the day's clutter, keep the gist, wake up fresh. More sleep-like tricks show up later.

## The quadratic wall

Managing what is in the window is half the battle. The other half: can the model afford to run attention over a giant one?

Every token compares with every other token. Double the window, quadruple the work. This is **quadratic** growth.

At a million tokens it is brutal — trillions of comparisons, for one answer, in every layer.

## Making big windows affordable

A million-token window should be impossible at that cost. Yet GLM, Kimi and others ship them. They skip the naive algorithm.

Most comparisons come out near zero anyway. A token only needs the few that matter. Models cut the cost in different ways:

- **Sparse index (GLM).** A cheap index picks the ~2,000 tokens worth scoring; full attention runs only on those. The same shortlist is *shared* across heads and layers, so the index barely costs anything. About **three times less work** at a million tokens.
- **Linear attention (Kimi).** Swap most layers for a cheaper kind whose cost grows in a straight line. It is weaker alone, so it is mixed with a few full-attention layers.
- **Sliding window (Gemma).** Most layers look only nearby; a few look everywhere.

GLM and Kimi bet differently — sparse versus linear — even as models otherwise converge.

## Closing

The model never changed. It is still the next-token predictor from [Transformers](/transformers).

Everything else did: a cache so it need not reread, subagents that start from cached blocks, compression when the talk grows long, and sparse attention so a giant window is affordable at all.

Context is not part of the model. It is the craft of choosing what to put in front of it.

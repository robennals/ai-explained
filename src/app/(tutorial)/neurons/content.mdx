<Ch slug="computation" /> introduced the *model*: a function with adjustable knobs, called parameters. A big enough model can compute almost any function you want, provided you can find the right parameters. <Ch slug="optimization" /> showed how to find them: make a tiny change that reduces the error, and repeat. That only works if the model is *smooth*, meaning a small change to a parameter makes a small, predictable change to the error.

So we want a model that does two things at once: it can compute almost anything, and it's smooth. A **neural network** is exactly that, which is why pretty much every modern AI system is built from one. This chapter builds one from scratch, starting with logic gates, which manage the first but not the second.

## Logic Gates Can Compute Anything, but Aren't Smooth

Every computer is built from **logic gates**: tiny components that combine true-or-false values, written as 1 and 0.

- **AND**: "Are *both* things true?" You need an umbrella if it's raining AND you're going outside.
- **OR**: "Is *at least one* thing true?" You'll get wet if it's raining OR someone sprays you with a hose.
- **XOR** (short for "exclusive or"): "Is *exactly one* thing true?" "You can have cake or ice cream" usually means one or the other, but not both.
- **NOT**: Flips the answer. NOT true is false, NOT false is true.

Tap the inputs to toggle them between 0 and 1. Switch between AND, OR, XOR, and NOT with the tabs. Tap the truth table rows to jump to that input combination.
</LogicGatePlaygroundWidget>

Wire gates together, with the output of one feeding the input of the next, and you can compute anything a computer can. A couple of gates can add two digits of binary (numbers written using only 0s and 1s). A few thousand gates flew astronauts to the Moon. The chip in your phone has billions.

<GateScaleWidget>
Step through the tabs, from one gate to billions. You don't need to follow how any of these circuits work. Just notice that every one is built from the same simple gates, wired together.
</GateScaleWidget>

But you can't train a circuit of gates. Its knobs are choices like "is this gate an AND or an OR?", and you can't make a gate 1% more like an OR. Its outputs snap between 0 and 1, so a small change either does nothing or flips the answer completely. There's no slope to follow.

<KeyInsight>
**Logic gates can compute anything, but they aren't smooth.** What we want is something that acts like a logic gate, but whose behavior slides smoothly as you turn its knobs. We'll build it in two steps.
</KeyInsight>

## Step 1: Gates Controlled by Numbers

Logic gates work on 0 (false) and 1 (true). But what if, rather than just 0 or 1, an input could be any number between 0 and 1? Then 0.2 could mean "probably not", 0.5 "not sure", and 0.9 "almost certainly". That's closer to the real world, where we're rarely completely sure of anything. So here's a way to compute AND that works with numbers like these: add up the two inputs, and if the total is more than 1.5, output 1. Otherwise output 0. When the inputs are exactly 0 or 1, only 1 + 1 gets over 1.5, so this is exactly AND.

<ThresholdGateWidget gate="AND">
Tap each row of the table and check that the output matches AND. Then slide the inputs to in-between values and read what each one means. How sure do both inputs need to be before AND says yes?
</ThresholdGateWidget>

OR works the same way with a lower bar: output 1 if the total is more than 0.5. Any single 1 gets over that.

<ThresholdGateWidget gate="OR">
Tap each row and check that the output matches OR. The only difference from AND is where the bar sits.
</ThresholdGateWidget>

NOT needs one more idea: multiply the input by −1 before adding. Then output 1 if the total is more than −0.5. An input of 0 gives a total of 0, which is more than −0.5, so the output is 1. An input of 1 gives −1, which isn't, so the output is 0.

<ThresholdGateWidget gate="NOT">
Slide the input from 0 to 1 and watch the total move the *other* way. Multiplying by −1 is what flips the answer.
</ThresholdGateWidget>

All three gates follow the same pattern, so we can make one machine that can be any of them:

1. Multiply each input by a number called its **weight**. The weight says how much that input counts, and a negative weight means the input counts *against* the answer.
2. Add up the weighted inputs, plus one more number called the **bias**. The bias plays the role of the bar: a bar of 1.5 is the same as a bias of −1.5 with a bar of 0.
3. If the total is more than 0, output 1. Otherwise output 0. We'll call this the **cutoff**.

<CutoffGateWidget>
Tap AND, OR, and NOT A to see the weights and bias for each gate, and check the table underneath. Then set the knobs yourself. Can you find other settings that also compute AND? What does a weight of 0 do?
</CutoffGateWidget>

This is real progress. Which gate we get is no longer a choice between separate parts. It's set by numbers, the weights and the bias, and those are knobs, just like the knobs of the models in <Ch slug="computation" />. (This add-then-compare machine is called a *perceptron*, and it was invented in 1958.)

But it's still not smooth. Try nudging the bias in the playground above: the output doesn't change at all, until suddenly it flips from 0 to 1. That's the stepped curve from <Ch slug="optimization" /> again.

## Step 2: Replace the Cutoff With a Slope

The fix is to replace the sudden cutoff with a smooth S-shaped curve called the **sigmoid**. It squashes any number into the range 0 to 1. Large positive totals become close to 1. Large negative totals become close to 0. Totals near 0 get a graded value in between. Think of it as a **dimmer switch** instead of a light switch: instead of snapping between off and on, it slides smoothly between them.

<SigmoidExplorerWidget>
Drag the input slider left and right. The output stays glued near 0 or 1 for extreme values, but changes rapidly in the middle. Where does the steepest part of the curve fall?
</SigmoidExplorerWidget>

The key property for us: when you change a weight by a small amount, the output now changes by a small amount. No sudden jumps. That's exactly what <Ch slug="optimization" /> told us we need.

## The Artificial Neuron

Put the two steps together and you have an **artificial neuron**, the building block of every neural network. A neuron does two things:

1. **Weighted sum.** Multiply each input by its weight, add them up, and add the bias.
2. **Activation function.** Pass the result through a smooth function, such as the sigmoid, that decides how strongly to output. This is called the **activation function**.

The name comes from brain cells, which (very roughly) do something similar: they add up signals from their neighbors and fire if the total is high enough. But you don't need any biology to follow the rest of this tutorial. Below is the same machine you played with in Step 1, with the cutoff swapped for the sigmoid.

<NeuronFreePlayWidget>
Tap **AND**, **OR**, **NOT A**, and **NAND** and watch the weights glide to each gate. Unlike the cutoff machine, the output now slides smoothly as the weights move, instead of jumping. Then slide the inputs to in-between values and see how the output responds. Finally, try to set the knobs so the neuron computes XOR.
</NeuronFreePlayWidget>

This neuron has two inputs, so that it can work like a logic gate. Real neurons can have many more. Neurons in modern AI systems often have thousands of inputs, each with its own weight. The recipe stays the same: multiply each input by its weight, add them all up along with the bias, and pass the total through the activation function.

With the right weights, a single neuron computes AND, OR, NOT, and more, and you can slide smoothly from one gate to another. One gate is missing, though: no settings of a single neuron compute XOR. We'll see why, and how to fix it, in a moment. A neuron also keeps the nuance of in-between inputs. The cutoff in Step 1 squashed them into a hard yes or no, so 0.8 AND 0.8 ("probably" and "probably") came out as a flat 1 ("definitely"). A neuron's output can be 0.73 ("probably") or 0.4 ("maybe not"). That matters because real-world data is rarely cleanly true or false. Is this email spam? Probably. Is that shadow in the photo a cat? Maybe.

## Sharp or Smooth

You can control how gate-like a neuron is. Multiply all the weights and the bias by a large number and the S-curve steepens toward a hard cutoff, so the neuron behaves just like a logic gate. Scale them down and it flattens into a gentle slope. The point where it switches stays in the same place. Only the sharpness changes.

<SharpnessExplorerWidget>
Drag the sharpness slider all the way up. The curve snaps almost like a light switch, 0 or 1, nothing in between. Now drag it down. The curve becomes a gentle slope.
</SharpnessExplorerWidget>

There's a catch, though. Very sharp neurons are harder to train. On the flat parts of a sharp sigmoid, the output barely changes when you nudge a weight, so the optimizer can't tell which direction to move. Real networks use various tricks to keep neurons in the smooth, trainable middle of the curve, but the basic intuition is enough for now: smoother neurons are easier to train.

<KeyInsight>
**A neuron is a smooth, trainable logic gate.** With the right weights it can compute AND, OR, NOT, and more. Because small changes to the weights produce small changes in the output, we can find those weights using optimization. And neurons handle in-between values naturally, which suits messy, uncertain real-world data.
</KeyInsight>

## Three Neurons Solve XOR

Logic gates become powerful when you wire them together, and the same is true of neurons. The simplest example is **XOR**, the "one or the other, but not both" gate from earlier in this chapter. As you saw above, a single neuron can't compute it: no matter what weights you try, you can't get all four input combinations right at once. But two neurons feeding into a third can. The two middle neurons are called **hidden neurons**, because they don't produce the final answer. They compute intermediate results that the output neuron needs:

- **Hidden Neuron 1** computes OR: "is *at least one* input on?"
- **Hidden Neuron 2** computes NAND (not-and): "are they *not both* on?"
- **Output neuron** computes AND of those two results: "at least one is on, AND they're not both on." That's XOR.

</TwoNeuronXORWidget>

<Callout type="info" title="The XOR Crisis">
In 1969, Minsky and Papert published *Perceptrons*, proving that single-layer networks can't solve XOR. This was taken as proof that neural networks were a dead end, and it killed most neural network research for over a decade: the "AI winter." The fix was always sitting there, obvious in hindsight: use more than one layer.
</Callout>

## Neural Networks

A **neural network** is just many neurons wired together like this, arranged in **layers**. Each neuron takes its inputs from the layer before and passes its output to the layer after. Every connection has its own weight, and every neuron has its own bias. Together, those weights and biases are the network's knobs, which training adjusts.

<NetworkOverviewWidget>
Tap the different neurons to see what each type does.
</NetworkOverviewWidget>

XOR needed a single hidden layer computing intermediate facts. Harder problems need many. You can't jump straight from raw pixels to "that's a cat," so you build up through stepping stones. The first hidden layer might detect simple patterns: edges, color patches, textures. The next combines those into parts: eyes, ears, fur. A later layer combines *those* into whole objects: "cat" or "dog." GPT-3 has 96 layers and frontier models today likely have more.

No human decides what each layer computes. The network learns that as part of its training, using the same recipe as always: make a tiny change to the knobs that reduces the error. Every weight affects the final output, so for every weight we can work out which way to nudge it to reduce the error (its **gradient**, from <Ch slug="optimization" />). An algorithm called **backpropagation** works this out for every weight at once, by flowing the error signal backward through the layers.

## Smooth, and Able to Compute Anything

Now we can see why the neural network meets both goals from the start of this chapter. Any neuron can act as a logic gate, and logic gates wired together can compute anything, so a big enough network with the right weights can do whatever a circuit can (and, because neurons handle in-between values, it isn't limited to 0s and 1s). And every weight is a smooth knob, so tiny improvements can find the right settings.

That said, "smooth logic gates" is only one way to think about neural networks, and trained networks rarely look like tidy circuits. They can do a lot more than generalize boolean logic, and as you go through this tutorial you'll meet better ways to think about them: in <Ch slug="vectors" />, a neuron becomes a detector that asks "is this input the kind of thing I'm looking for?", and in <Ch slug="embeddings" />, a network's numbers turn out to describe meanings. The link to logic gates is useful here because it explains why neural networks give us what this chapter needed: a model that can compute almost anything, and is smooth enough to train.

<Callout type="info" title="One limit">
A network, like a circuit, gives its answer in a single pass: the input flows through a fixed number of layers and out the other side. Some problems need more steps of work than that, however large the network is. A computer handles those by looping, running the same circuit again and again. In <Ch slug="reasoning" /> we'll see how language models get the same power: they *think* by writing out their working, then reading it back in, as many times as the problem needs.
</Callout>

<KeyInsight>
**A neural network is a model that is both smooth and able to compute almost anything.** It can do what a circuit of logic gates can do, but because it's smooth, optimization can find the right weights. That combination is why neural networks power pretty much all of modern AI.
</KeyInsight>

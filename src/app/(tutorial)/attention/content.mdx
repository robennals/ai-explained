In order to understand what a word means, we need to look at other words in the document, including words that might have occurred much earlier. The technique models AI models use to do that is called "Attention". In this chapter we'll explain how it works.

## Some Tokens Need Other Tokens

You often can't tell what a token means on its own. Take "bank": is it a place for money, or the side of a river? You have to look at the tokens around it. A token like "it" is even harder, because it can refer to pretty much anything and we don't know what it is referring to unless we look back to find what it refers to.

Different tokens need different things in order for us to understand what they mean. "it" needs the thing it stands for. "opened" needs whoever did the opening. "sky" needs the planet it hangs over. "treaty" needs a name from pages ago.


## Searching for a Match

So how do we know which tokens we need to "pay attention to" in order to understand the meaning of a particular token?

The "Attention" algorithm does this by giving each token three things:

- A token's **query** is what it is looking for, like the words you type into a search box.
- A token's **key** is what it advertises to the other tokens, like the title of a web page.
- A token's **value** is the information it provides if you pay attention to it, like the contents of the page.

To understand a token, we take that token's **query** and compare it against every other token's **key** to find the tokens whose **keys** seem most similar to our **query**.

## Matching with the Dot Product

How does a computer decide whether a query matches a key? So far the have been in plain English, but comparing English text is tricky. How do we know that "A place with a sky" matches "A planet"?.

In [Chapter 4](/vectors) and [Chapter 5](/embeddings) we showed that AI model can represent arbitrarily complex things using vectors. We also showed that we can use the dot product to compare two vectors to see how similar their meanings are. 

Indeed this is how Attention compares a query to a key. The query and key are both vectors, and we use the dot product to determine how well the query vector matches a particular key vector.

</MatchingQuestionsWidget>

From here on we'll write each query and key in plain English and the match as a single score. Underneath they're still vectors and dot products.

## Dividing Your Attention

Usually more than one token matches, at least a little. So instead of crowning a single winner, attention blends the values together, giving each token a say in proportion to how well it matched. To do this, we want to take the raw scores we got from the dot product, and turn them into percentages that add up to 100%.

Most AI models do this using a function called **softmax**. Softmax makes sure the percentages always add up to 100%, while giving a greater share to tokens that had bigger scores.

<SoftmaxExplorerWidget>
Drag the sliders. Try "All equal": everyone gets 25%. Try "Moderate, rest silent": A wins by default because nobody else is saying anything. Try "Moderate meets loud": B drowns out A. The gaps between scores matter more than the absolute values. Softmax cares about who's loudest *relative to everyone else*.
</SoftmaxExplorerWidget>

The gap between the scores is what matters. When one token is the clear best match, it takes almost all of the attention. When two tokens tie, the attention splits evenly between them. We'll see both cases when we gather the values.

## What Did You Find?

The reason we pay attention to another token is to extract information from it. That information is the token's **value**, which is yet another vector.

You could imagine a simplified version of attention that just picked the token that matched the best and returned that token's value. But Attention is smarter than that. It combines the values of all the tokens, weighting each by it's softmax percentage.

It's kind of crazy that this works. Why should you be able to blend these value vectors together and get something that makes any sense? But, as we saw in [Chapter 5](/embeddings), the embeddings used by AI models are constructed such that you can do things like take the average of two emmedding vectors, and the result is a vector that combines their meanings.

<AttentionValuesWidget>
Try "A clear value": "it" pays almost all its attention to "glass", so it gathers "the glass". Try "An even split": "it" could be the cat or the dog, so it gathers "either the cat or the dog". Try "A leaning blend": "pounced" is looking for the agile animal that pounced, which fits the cat better than the dog, so it gathers "probably the cat, maybe the dog".
</AttentionValuesWidget>

## When Nothing Matches

Sometimes a token looks for something that isn't there. The "it" in "It was raining" doesn't stand for anything; English just wants a subject. So what does "it" pay attention to, given that the softmax scores are required to sum to 100%?

The fix is a **sink**: an extra token whose value means "nothing" and that faintly matches everything. A real answer easily beats it, but with no real answer the sink wins by default, so the token safely gathers nothing.

<AttentionSinkWidget>
Try "Nothing matches": no real token fits, so the sink takes most of the attention and "It" gathers nothing. Try "Something matches": "glass" scores far above the sink, so it wins and the sink is ignored.
</AttentionSinkWidget>

Real models don't always add a dedicated sink token. Often they just learn to dump spare attention on a comma, the first token, or the token itself.

## Where the Vectors Come From

Where do a token's query, key, and value actually come from? You don't need to write them by hand. The model uses a neural network to compute them from the tokens embedding, and we use optimization to train the neural network to produce the queries, keys, and values that do the best job at predicting the next token of the training data.

## Multi-Headed Attention

In the examples we've given so far, each token only has a single query. But in practice, there are often lots of different kinds of information we might want in order to understand the meaning of a token. Where is this happening? who did this action? Which of several meanings of this word might be relevant?

So in practice we usually do **multi-headed attention**. We have multiple **attention heads**, each of which computes a different query, key, and value for each token. We also usually have multiple layers of attention, where each layer adds more information on top of what was gathered by the previous layers.

You'll see this in more depth when we discuss Transformers in [Chapter 9](/transformers).


## What We've Built

Attention is:

1. **Query, key, value.** Each token looks for something (query), advertises what it has (key), and offers an answer (value), like a search.
2. **Match scores.** The dot product of a query and a key scores how well two tokens fit.
3. **Softmax.** Turn those scores into percentages that add up to 100%.
4. **The sink.** A safe place for attention to go when nothing in the sentence fits.
5. **Blended values.** Combine the chosen values using those percentages.
6. **Many heads.** Run the whole thing many times over, each head looking for something different.

One thing is still missing: attention has no idea *where* the tokens are, only *what* they are. "The dog chased the cat" and "the cat chased the dog" give exactly the same scores. The next chapter fixes that with a trick involving rotation.

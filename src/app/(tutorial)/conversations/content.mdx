A model completes text. It does not take turns, remember what you said, or know that a conversation is happening. Yet talking to one feels like talking to someone who does all three. This chapter is about the plumbing that produces that illusion, and it is simpler than you might expect.

## Making It a Conversation

Underneath every chat interface there is a single stream of tokens. The model does not see a conversation. It sees a prompt and writes a completion, exactly as a base model does. Post-training (<Ch slug="post-training" />) is what changed the completion from whatever text would plausibly have come next into an answer. What makes it a conversation is markers in the prompt saying who is speaking.

</TranscriptViewsWidget>

The format is called a *chat template*. Every turn is opened and closed, and the markers are real tokens the tokeniser knows about. The program running the model writes the human turns and the marker that opens the model's turn. The model writes its reply, and then the marker that closes it, which is how the program knows the reply has finished. The exact markers vary from model to model, though the shape does not.

## Repeated Turns

A real conversation is several turns. The way we handle that is simple. Each time you send a message, we pass the model every message so far, including the ones it wrote itself, and ask it to complete the text by saying what comes next.

<RepeatedTurnsWidget>
Step through the three replies and watch the prompt grow. Everything the model said earlier is in there too, sent again. Switch to **As messages** to see the same thing as the conversation you would see on screen.
</RepeatedTurnsWidget>

The model is run fresh every time. Its only knowledge of its past self is the messages we tell it it wrote.

It might seem wasteful to make the model re-read the whole conversation before every reply. As <Ch slug="context" /> shows, it can be made efficient by caching the attention vectors for prefixes the model has already seen, so the re-reading is mostly free.

## The System Prompt

There is one more message in a real conversation, and you never see it. Before your first message, the program puts a *system prompt* at the top: text telling the model things it could not have learned during training. What it is called and how it should behave. Today's date. Where you are.

<SystemPromptViewWidget>
Switch between the two views. It is the same stream of tokens as before, with one more message at the front, and that message is the one you are not shown.
</SystemPromptViewWidget>

The system prompt is nothing more special than text at the top of the prompt. That is why it works at all, and also why it is not a hard guarantee: it is not a rule the model is forced to obey, only text it is completing a document after.

From here on, this tutorial draws conversations as messages rather than as raw tokens, because they are easier to follow. A message drawn with a dashed outline, like the system prompt above, is one the human is never shown.

## Putting It Together

Turning a next word predictor into something you can talk to takes two things. <Ch slug="post-training" /> was the first: steering the model towards the kind of completion that reads like a helpful reply. This chapter was the second, and none of it is training at all. A program arranges the exchange as one document, hands the whole thing over every turn, and presents what comes back as a conversation.

The transformer is doing the same thing it was doing at the end of <Ch slug="transformers" />, predicting one token at a time. What changed is what it gets asked to predict, and who arranges the text it predicts from.

The next two chapters add the rest of what a chat product does. <Ch slug="reasoning" /> gives the model room to think before it answers. <Ch slug="agents" /> lets it act on the world rather than only talk about it, using hidden messages exactly like the system prompt above.

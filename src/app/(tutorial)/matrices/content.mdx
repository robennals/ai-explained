# A Thousand Questions at Once

<Lead>
The graphics card that runs ChatGPT was invented to make videogames look good. The same operation that spins a 3D dragon across your screen is the operation a neural network uses to think. It's called matrix multiplication. By the end of this chapter you'll see why one kind of chip does both jobs.
</Lead>

## You Already Know This

A matrix sounds like a new and scary object. It isn't. A matrix is just a list of weight-vectors, one detector each, and you dot-product the input against every one of them.

Remember the bear detector from the Vectors chapter. You take an animal's property-vector (big, scary, hairy, cuddly, fast, fat) and dot it with a "bear" weight-vector. Out comes a single number: how bear-like this animal is. One dot product, one detector.

Written with a dot, `bear · cat` means the dot product: multiply each matching property and add up the results, giving a single number for how bear-like the cat is. That dot is the same similarity score from the Vectors chapter, now with a shorter name.

Now suppose you want a bear detector *and* an eagle detector *and* a snake detector, all at once. Keep them as a list of three weight-vectors and run each one's dot product against the same input animal. The animal goes in as six properties and comes out re-described as a handful of scores, maybe "0.8 bear-like, 0.4 eagle-like, 0.2 snake-like." That list of detectors is a **matrix**, and running every detector against an input is **matrix multiplication**. There is nothing in it you haven't already done by hand. Each detector is one dot product, and the matrix just asks all your questions at the same time.

<KeyInsight>
**A matrix is a stack of detectors.** Each one is a weight-vector, the same kind you used to build a single detector. One matrix multiply runs every detector at once and re-describes the input as a list of match scores.
</KeyInsight>

## Writing the Matrix as a Grid

You've now seen a matrix do its job: a list of detectors, each dot-producted with the input. The next thing to settle is how to write that list down, because the standard notation is what every later chapter uses.

Start from the pieces. An animal is a vector, a row of property numbers (big, scary, hairy, cuddly, fast, fat) shown as the same bars you've already seen. A detector is just an animal's vector too, used as a weight-vector instead of as an input.

To write several detectors together, stack each one as a **row**. The result is a **grid of numbers**, and that grid is the matrix. Each row is one animal you match against, and the six columns are the six properties. Nothing computes here; this is only the standard way to lay the detectors out on the page.

<MatrixGridWidget>
Choose which animals to match against and watch the grid gain or lose a labelled, boxed row. Each row is one detector, an animal's property vector laid out across the six columns, and the whole grid is the matrix.
</MatrixGridWidget>

From here on, "the matrix" means exactly this: a grid of stacked detector-vectors, one detector per row.

## Can You Get the Original Back?

Re-describing an animal as "how bear-like, how eagle-like, how snake-like" throws away the original properties and replaces them with match scores. Is that a one-way trip, or can you recover the animal you started with?

It depends on how many detectors you used. Pick as many varied reference animals as there are properties, and the new description holds onto everything. To prove it, build the matrix that runs the re-description backwards. That matrix is called the **inverse**, and applying it recovers the exact original animal. The whole thing was a change of vocabulary, like translating to another language and back. Nothing was lost.

Use fewer reference animals than there are properties and there's no way back. Six properties squeezed into three numbers means three numbers got dropped, and no inverse can guess what they were. The detail is gone. That lossy squeeze is exactly what a neural-network layer does when it shrinks a representation, and it's the seed of how embeddings pack meaning into a smaller space.

<RoundTripWidget>
Start with six good reference animals and watch the inverse recover the original exactly. Now drop down to three. The squeeze leaves only three numbers to describe a six-property animal, and the original is unrecoverable. Try different small sets to see which animals become confusable.
</RoundTripWidget>

## A Layer of a Neural Network Is a Matrix (Plus a Bend)

A layer of a neural network takes an input vector and produces an output vector. It does this by running a stack of weighted sums, one per output. A weighted sum is a dot product. A stack of dot products is a matrix multiply. So a layer is a matrix multiply, the same operation from §1.

There's one difference from the bear-eagle-snake matrix. We hand-picked those detectors. A neural network learns its own during training. It works out for itself which reference concepts are worth detecting, and those learned detectors become the rows of its weight matrix. Nobody tells it to build a bear detector. It builds whatever detectors make the next layer's job easier.

A layer is not *only* a matrix, though. After the matrix produces its output vector, the layer applies an **activation function** to that whole vector at once: it subtracts a bias and then bends each value, zeroing out the weak matches. So a layer is a matrix multiply, then a bend. The next section is about why the bend has to be there.

Drag the threshold up and watch more detectors fall silent. The strong matches survive; the weak ones are cut. (ReLU and sigmoid are covered properly in the Training chapter.)

## Why the Bend Can't Be Dropped

Stack two matrix multiplies back to back with nothing between them and something deflating happens. You can multiply the two matrices together first and get a single matrix that does both at once. Two layers collapse into one. So pure matrix layers buy you no extra power from depth: a hundred of them stacked is still just one matrix in disguise.

This is why the bend from §3 earns its place. Put a nonlinear activation function between two matrix layers and they can no longer be merged. The bend is what lets a deep network do things no single matrix could.

</MatrixCompositionWidget>

<KeyInsight>
**Matrix times matrix is just one matrix.** Depth alone buys nothing. A nonlinear bend between the layers is what makes stacking worthwhile.
</KeyInsight>

## Attention Is a Matrix Multiply Too

The Attention chapter had the word "it" looking back through a sentence for a noun to attach to. The way it scored each candidate was a dot product: the query of "it" against the key of every other token.

Run that for all the candidates at once and you have a detector stack. Stack the other tokens' keys as the rows of a matrix, multiply by this token's query vector, and out come the match scores, one per token. It's the same picture as §1. The keys are the detectors and the query is the input. One matrix times a vector, per token, per head.

The query, key, and value vectors are themselves produced by matrix multiplies, and blending the chosen values together is one more. Attention is matrix multiplication the whole way down.

Multiplying by the query for "it" gives a match score for each: the nouns score high, the filler scores low. Same operation as the detector stack, with keys for rows and a query for the input.

## The Same Math Spins 2D and 3D Worlds

Time to close the loop on the cold open. The exact same multiply-and-add that re-describes an animal also re-describes a point's position in space. Feed a point's coordinates through the right matrix and it comes out rotated.

Every frame of a 3D game does this to every vertex of every model: multiply by a matrix to spin the world, tilt the camera, and pose the character. A single frame is millions of these multiply-adds. So chipmakers built graphics cards that do millions of them in parallel, all for the sake of games.

Then neural networks turned out to be mostly matrix multiplication as well. The same chips built to spin dragons were already perfect for running detector stacks by the million. The hardware for games became the hardware for AI. That's the answer to the puzzle from the top of the chapter.

## What's Next

A neural network is a stack of these matrices, one per layer, with a bend after each. Its whole skill lives in the numbers inside those matrices, the learned detectors. Training is the search for the right numbers. The next chapters are about how that search works: how gradient descent feels its way downhill to the matrices that solve the problem.

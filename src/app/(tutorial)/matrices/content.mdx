# A Thousand Questions at Once

<Lead>
The graphics card that runs ChatGPT was invented to make videogames look good. The same operation that spins a 3D dragon across your screen is the operation a neural network uses to think. It's called matrix multiplication. By the end of this chapter you'll see why one kind of chip does both jobs.
</Lead>

## A Matrix Is a Grid of Vectors

In the Vectors chapter, each animal was a **vector** — a list of property numbers (big, scary, hairy, cuddly, fast, fat). The chapter always drew that list as a **column**: one property per line, stacked top to bottom. A cat's column of six numbers is the cat's vector.

That same list of numbers can also be written as a **row**, spread left to right, one cell per property. Column or row, the numbers are identical — just the layout has changed.

<VectorOrientationWidget>
Pick an animal and compare the two panels: the column on the left is the same card from the Vectors chapter; the row on the right shows the same six values laid out horizontally, one boxed cell per property.
</VectorOrientationWidget>

Once vectors are written as rows, you can stack several animals on top of each other and the result is a **grid of numbers**. That grid is a **matrix**. Each row is one animal; each column is one property — so the cat's "scary" number sits in the same column as the bear's. A matrix built from a list of animals is just their vectors written out together.

<MatrixGridWidget>
Choose which animals go in the matrix and watch the grid gain or lose a labelled, boxed row. Each row is one animal's property vector laid out across the six property columns, and the whole grid, all the rows together, is the matrix.
</MatrixGridWidget>

<KeyInsight>
**A matrix is a grid of vectors.** Stack a list of vectors as rows and the grid you get is a matrix. Here each row is an animal and each column is a property.
</KeyInsight>

## Multiplying a Vector by a Matrix

Now that the animals are stacked into a matrix, you can multiply a vector by it. Multiplying a vector by a matrix means taking the **dot product** of the input vector with every row of the matrix and collecting the results into a new output vector.

The dot product is from the Vectors chapter. Written with a dot, `bear · cat` means: multiply each matching property and add up the results, giving a single number for how bear-like the cat is. Each row of the matrix acts as a detector. Its dot product with the input says how much the input matches that row.

So one matrix multiply runs every row's dot product at once. Feed in a cat and the bear row scores it for bear-likeness, the eagle row for eagle-likeness, the snake row for snake-likeness. The input vector of six properties comes out re-described as a new output vector, one match score per row.

<DetectorStackWidget>

Read down the output column on the right to see each animal-row's dot product with your input, one match score per row. Click any row to expand the full working and watch that dot product computed property by property, every matching pair multiplied and added up.
</DetectorStackWidget>

<KeyInsight>
**Matrix multiplication is a stack of dot products.** A vector goes in, and the dot product of that input with each row comes out as one number, so the result is a new vector with one score per row.
</KeyInsight>

## A Layer of a Neural Network Is a Matrix (Plus a Bend)

A layer of a neural network takes an input vector and produces an output vector. It does this by running a stack of weighted sums, one per output. A weighted sum is a dot product. A stack of dot products is a matrix multiply. So a layer is a matrix multiply, the same operation from the previous section.

There's one difference from the bear-eagle-snake matrix. We hand-picked those detectors. A neural network learns its own during training. It works out for itself which reference concepts are worth detecting, and those learned detectors become the rows of its weight matrix. Nobody tells it to build a bear detector. It builds whatever detectors make the next layer's job easier.

A layer is not *only* a matrix, though. After the matrix produces its output vector, the layer applies an **activation function** to that whole vector at once: it subtracts a bias and then bends each value, zeroing out the weak matches. So a layer is a matrix multiply, then a bend. The next section is about why the bend has to be there.

Drag the threshold up and watch more detectors fall silent. The strong matches survive; the weak ones are cut. (ReLU and sigmoid are covered properly in the Training chapter.)
</LayerDetectorWidget>

## Why the Bend Can't Be Dropped

Stack two matrix multiplies back to back with nothing between them and something deflating happens. You can multiply the two matrices together first and get a single matrix that does both at once. Two layers collapse into one. So pure matrix layers buy you no extra power from depth: a hundred of them stacked is still just one matrix in disguise.

This is why the bend from the previous section earns its place. Put a nonlinear activation function between two matrix layers and they can no longer be merged. The bend is what lets a deep network do things no single matrix could.

<MatrixCompositionWidget>
Edit the numbers in matrices A and B and watch the product matrix C update. C does the work of both A and B in a single step. Now flip on "Put an activation between them." C grays out, because once there's a bend in the middle, no single matrix can stand in for the pair.
</MatrixCompositionWidget>

<KeyInsight>
**Matrix times matrix is just one matrix.** Depth alone buys nothing. A nonlinear bend between the layers is what makes stacking worthwhile.
</KeyInsight>

## Attention Is a Matrix Multiply Too

The Attention chapter had the word "it" looking back through a sentence for a noun to attach to. The way it scored each candidate was a dot product: the query of "it" against the key of every other token.

Run that for all the candidates at once and you have a detector stack. Stack the other tokens' keys as the rows of a matrix, multiply by this token's query vector, and out come the match scores, one per token. It's the same picture as the detector stack from the start of the chapter. The keys are the detectors and the query is the input. One matrix times a vector, per token, per head.

The query, key, and value vectors are themselves produced by matrix multiplies, and blending the chosen values together is one more. Attention is matrix multiplication the whole way down.

This is the worked example from the Attention chapter. The keys of "cat", "dog", and the filler "blah" are stacked as rows. Multiplying by the query for "it" gives a match score for each: the nouns score high, the filler scores low. Same operation as the detector stack, with keys for rows and a query for the input.
</AttentionMatmulWidget>

## The Same Math Spins 2D and 3D Worlds

Time to close the loop on the cold open. The exact same multiply-and-add that re-describes an animal also re-describes a point's position in space. Feed a point's coordinates through the right matrix and it comes out rotated.

Every frame of a 3D game does this to every vertex of every model: multiply by a matrix to spin the world, tilt the camera, and pose the character. A single frame is millions of these multiply-adds. So chipmakers built graphics cards that do millions of them in parallel, all for the sake of games.

Then neural networks turned out to be mostly matrix multiplication as well. The same chips built to spin dragons were already perfect for running detector stacks by the million. The hardware for games became the hardware for AI. That's the answer to the puzzle from the top of the chapter.

## What's Next

A neural network is a stack of these matrices, one per layer, with a bend after each. Its whole skill lives in the numbers inside those matrices, the learned detectors. Training is the search for the right numbers. The next chapters are about how that search works: how gradient descent feels its way downhill to the matrices that solve the problem.
